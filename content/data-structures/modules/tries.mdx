<Explanation id="intro">

A **trie** (prefix tree) stores strings character by character down a tree,
so that every word sharing a prefix shares the same path from the root.
It's the structure behind autocomplete and spell-check.

```python
trie = {}
node = trie
for ch in "cat":
    node = node.setdefault(ch, {})
node["#"] = True   # marks "this path spells a complete word"
```

After inserting `"cat"` and `"car"`, the trie looks like:
`{'c': {'a': {'t': {'#': True}, 'r': {'#': True}}}}` — the shared `"ca"`
prefix is stored once.

</Explanation>

<CodeExample id="try-it" language="python" code={`def trie_search(trie, word):\n    node = trie\n    for ch in word:\n        if ch not in node:\n            return False\n        node = node[ch]\n    return "#" in node\n\ntrie = {}\nnode = trie\nfor ch in "cat":\n    node = node.setdefault(ch, {})\nnode["#"] = True\n\nprint(trie_search(trie, "cat"))  # True\nprint(trie_search(trie, "ca"))   # False — "ca" was never inserted as a complete word`} caption="trie_search fails a prefix that was never marked complete with the # marker, even though every character on the path exists — that's the whole point of the marker." />

<Explanation id="use-cases">

Compare a trie to a hash set of all words for the query "find every word
starting with `pre`": a hash set has to check every single entry — O(n).
A trie walks 3 characters down from the root, then reads off every word in
that subtree — the cost depends on the prefix length and result size, not
the total dictionary size. That's the trade a trie makes: slower/bigger
than a hash set for exact single-word lookup in practice, but built for
prefix queries a hash set simply can't do efficiently.

</Explanation>

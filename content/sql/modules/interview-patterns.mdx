<Explanation id="intro">

SQL interview questions rarely test obscure syntax — they test whether
you reach for the right *pattern* under time pressure. A few show up
constantly enough to be worth recognizing on sight, combining tools you
already have from this course.

**"Nth highest value"** — sort, then skip:

```sql
SELECT name, salary FROM employees
ORDER BY salary DESC
LIMIT 1 OFFSET 1;   -- skip the top 1, take the next 1 = 2nd highest
```

`LIMIT n OFFSET m` means "skip the first `m` rows of the (ordered)
result, then take the next `n`." For the 3rd-highest, you'd use `OFFSET
2`, and so on.

</Explanation>

<CodeExample id="try-it" language="sql" code={`CREATE TABLE employees (id INTEGER, name TEXT, department TEXT, salary INTEGER);\nINSERT INTO employees VALUES\n  (1, 'Ada', 'Engineering', 145000),\n  (2, 'Grace', 'Engineering', 152000),\n  (3, 'Ken', 'Sales', 98000);\n\n-- \"Which department has the most employees?\"\nSELECT department, COUNT(*) AS n\nFROM employees\nGROUP BY department\nORDER BY n DESC\nLIMIT 1;`} caption="'Group, aggregate, sort, take the top one' is the single most common interview pattern — it answers almost any 'which X has the most/highest/fewest Y' question." />

<Explanation id="patterns">

A couple more patterns worth having ready:

**"Find duplicates"** — group by the value, keep groups with count > 1:

```sql
SELECT department FROM employees
GROUP BY department
HAVING COUNT(*) > 1;
```

**"Rows in A but not in B"** — a `LEFT JOIN` where the right side didn't
match:

```sql
SELECT employees.name
FROM employees
LEFT JOIN departments ON employees.department_id = departments.id
WHERE departments.id IS NULL;   -- no matching department row
```

Under real interview time pressure, these patterns are worth recognizing
by shape ("this is a top-N question," "this is a duplicates question")
rather than re-deriving the SQL from scratch each time.

</Explanation>

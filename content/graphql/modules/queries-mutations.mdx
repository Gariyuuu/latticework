<Explanation id="intro">

A **query** reads data; a **mutation** changes it — but in GraphQL,
both shapes look similar: you send a request, and get back exactly the
fields you asked for. A mutation just also applies some change first.
This means a client can update a record and immediately see the
resulting fields it cares about, all in one round trip, using the exact
same `resolve` selection logic from the previous module.

```python
def apply_mutation(data, updates, query):
    updated = dict(data)
    updated.update(updates)
    return resolve(query, updated)
```

</Explanation>

<CodeExample id="try-it" language="python" code={`# resolve() as defined in the previous module\ndef apply_mutation(data, updates, query):\n    updated = dict(data)\n    updated.update(updates)\n    return resolve(query, updated)\n\nuser = {"id": 1, "name": "Alice", "age": 30, "email": "alice@old.com"}\n\n# "update this user's email, and give me back just the name and new email"\nprint(apply_mutation(user, {"email": "alice@new.com"}, {"name": True, "email": True}))\n# {'name': 'Alice', 'email': 'alice@new.com'} -- one round trip: write, then read exactly what changed`} caption="The original 'user' dict itself is never mutated in place -- apply_mutation builds a NEW dict via dict(data) then .update(updates), the same immutable-update discipline from Functional Programming's pure-functions module, applied here so the caller's original data stays untouched." />

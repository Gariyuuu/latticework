<Explanation id="intro">

Neither a monolith (one deployable codebase) nor microservices (many
independently deployable services) is universally "better" — it's a
genuine tradeoff. Microservices buy independent deployment and scaling
per-service, at the cost of real operational complexity (network calls
where function calls used to be, distributed tracing, more
infrastructure to run). That cost is worth paying once a few conditions
line up: a large enough team that a shared monolith becomes a bottleneck,
frequent independent deploys, or components with genuinely different
scaling needs.

```python
def recommend_architecture(team_size, deploy_frequency_per_week, independent_scaling_needed):
    score = 0
    if team_size > 20:
        score += 1
    if deploy_frequency_per_week > 5:
        score += 1
    if independent_scaling_needed:
        score += 1
    return "microservices" if score >= 2 else "monolith"
```

</Explanation>

<Explanation id="intro">

Every HTTP exchange is a **request** (client → server) followed by a
**response** (server → client), each with the same basic shape: a
start line, headers, and an optional body. A request's start line has
three parts:

```
GET /api/users HTTP/1.1
```

`GET` (the **method** — what kind of action), `/api/users` (the
**path** — which resource), `HTTP/1.1` (the **protocol version**).

```python
def parse_request_line(line):
    method, path, version = line.split(" ")
    return method, path, version
```

</Explanation>

<Explanation id="status-codes">

A response's start line begins with a **status code** — a 3-digit number
whose FIRST digit tells you the general category:

| Range | Meaning |
|---|---|
| 2xx | Success (`200 OK`, `201 Created`) |
| 3xx | Redirection (`301 Moved`, `304 Not Modified`) |
| 4xx | Client error (`404 Not Found`, `401 Unauthorized`) |
| 5xx | Server error (`500 Internal Server Error`) |

```python
def status_line_ok(status_code):
    return 200 <= status_code < 300
```

A 4xx means "you (the client) did something wrong" — a 5xx means "the
server broke, and it wasn't your request's fault." That distinction
matters a lot when debugging: a 4xx points you at your request, a 5xx
points you at the server.

</Explanation>
